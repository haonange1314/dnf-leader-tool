# 12 人团本排表质量基线

最近复核：2026-09-09。该基线用于衡量自动排表调整是否破坏现有 12 人团本结果，与
`docs/performance-baseline.md` 的求解耗时基线互补。测试数据全部为合成匿名数据，不包含
真实玩家或角色信息。

当前内置 12 人团本为 v5，不配置秘宝、固定红队奶或群猎规则；质量画像不再要求任何特殊
角色覆盖。v5 在候选奶数量为 `3N～5N` 时启用动态目标组成：每队先分配 1 奶，额外奶依次
进入红队第 1～N 波、黄队第 1～N 波；奶位固定后再安排 C。求解器仍保留由副本版本驱动的
通用特殊角色扩展接口，但它不参与当前内置团本的质量目标。

## 运行方式

```bash
make test-quality
```

命令逐场景输出 JSON，包含求解状态、已安排人数、完整波次/队伍、目标组成、奶位、红队 C、
首尾配对、黄绿平均伤害浮动、C/奶跨波差、强度顺序冲突、各波人数、未分配原因及墙钟时间。
质量测试也包含在后端常规 pytest 和 `make check` 中。

使用 `preferred_composition_count` 限时质量下限，避免改变自定义副本和异常输入的既有行为。

## 不变量

每个场景同时验证：

- 同一角色最多出现一次。
- 同一玩家同一波最多出现一个角色。
- 队伍人数不超过副本版本容量。
- 完整队伍只能命中副本版本允许的组成。
- 锁定角色保留原波次和队伍。
- 未分配角色不会同时出现在排表中，摘要人数与实际安排一致。
- 当前内置团本的特殊规则满足数始终为 0。
- 正常 v5 输入的目标组成数量等于完整队伍数量，红队 C 位置全部填满。
- 黄绿完整队伍的平均伤害最大/最小浮动按本次排表参数计算，默认参数为 20%。

## 限时质量门槛

固定种子并不意味着每个限时阶段都能证明最优。阶段结果为 `FEASIBLE` 时，测试使用稳定的
下限或上限：复杂规则画像要求 C 跨波差不超过 55,000、奶跨波差不超过 450、强度顺序冲突
不超过 14；队伍限制画像要求 C 跨波差不超过 60,000、奶跨波差不超过 600、强度顺序冲突
不超过 13。结构目标始终优先于这些后级质量门槛。

求解器采用分阶段目标：先最大化安排人数并满足动态奶位/红队 C 硬结构，再依次固定奶位、
红队 C，随后优化完整度和前波填充、目标组成、黄绿浮动、自然语言规则、通用强度/跨波平衡
和玩家偏好。聚合模型只用于生成热启动，不裁剪候选角色、跳过锁定或改变副本版本规则。

## 后续扩展

真实数据调优继续使用匿名化画像。新增场景必须先定义角色唯一、玩家同波唯一、完整度等
结构性门槛，再根据多次固定种子结果设置限时质量上下限；不得把一次运行的具体排表写成
永久最优承诺。
